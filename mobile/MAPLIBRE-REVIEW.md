# MapLibre basemap dependency review

Review date: 2026-10-10. Scope: the manual mobile app's map engine
([decision 010](../docs/decisions/010-osm-maplibre-basemap.md), issue #27). No backend, contract
or collector changes.

## Selected versions

| Package | Version | Kind | Reason |
| --- | --- | --- | --- |
| react-native-webview | 13.16.1 | dependency | Exact version in Expo 57.0.17's `bundledNativeModules.json`, so it runs in Expo Go (decision 009). MIT. |
| maplibre-gl | 6.11.2 | devDependency | Released 2026-09-24. Latest patch of a minor line at least two weeks old; 6.12.0 and 6.13.0 were days old. BSD-3-Clause. |

`maplibre-gl` is a devDependency because only its `dist` files are used: the build script inlines
them into `src/map/maplibreBundle.generated.ts` (gitignored, regenerated by the npm
start/typecheck/test/build pre-hooks). Nothing loads from a CDN at runtime.

## Security review

- **GHSA-jrc7-96c5-q579** (critical, published 2026-09-08): XSS sanitizer bypass in
  `DOM.sanitize()`, affecting `maplibre-gl` <= 6.4.0. 6.11.2 is outside the range. This rules out the
  whole 5.x line, which also stopped receiving releases after 5.24.0 (2026-04-23). The page builds
  marker popups with `textContent`, never HTML, so server labels are not parsed as markup.
- **GHSA-36j3-xxf7-4pqg** (medium, 2020): Android WebView universal XSS in
  `react-native-webview` <= 10.10.2. 13.16.1 is outside the range. The WebView disables multiple
  windows, and the link guard opens any outside URL (such as attribution links) in the system browser.
- No install scripts in `maplibre-gl`, `react-native-webview` or the new transitive packages
  (`hasInstallScript` checked in the lockfile).
- `npm audit`: 22 advisories on this branch versus 23 on main. None are new. The one removed was
  reported through `react-native-maps` but originates in `react-native` itself and remains via that
  package. The pre-existing tooling advisories are listed in [SDK57-REVIEW.md](SDK57-REVIEW.md).
- `maplibre-gl` maintainers on npm: the MapLibre organization account and three core maintainers.
  Provenance: [maplibre/maplibre-gl-js](https://github.com/maplibre/maplibre-gl-js).

New transitive packages, all from `maplibre-gl` 6.11.2: `@mapbox/jsonlint-lines-primitives`,
`@mapbox/point-geometry`, `@mapbox/tiny-sdf`, `@mapbox/unitbezier`, `@mapbox/vector-tile`,
`@maplibre/geojson-vt`, `@maplibre/maplibre-gl-style-spec`, `@maplibre/mlt`, `@maplibre/vt-pbf`,
`@types/geojson`, `bidi-js`, `earcut`, `gl-matrix`, `json-stringify-pretty-compact`, `kdbush`,
`minimist`, `murmurhash-js`, `pbf`, `quickselect`, `require-from-string`, `tinyqueue`. They are
build-time only: only maplibre-gl's own prebuilt `dist` files reach the app.

## Upgrade procedure

1. Choose a release at least two weeks old and check advisories for `maplibre-gl` and
   `react-native-webview`.
2. Keep `react-native-webview` at the version Expo's `bundledNativeModules.json` lists for the SDK.
3. Run `npm run map:bundle --prefix mobile`. It fails if `maplibre-gl.mjs` or the worker stop
   importing `"./maplibre-gl-shared.mjs"` exactly once, or if the shared chunk gains relative
   imports. The WebView's Blob-URL rewrite depends on both.
4. Run typecheck, tests and export, then the device check below.

## Basemap service

OpenFreeMap ([openfreemap.org](https://openfreemap.org/)): free public instance with no key,
registration, cookies or request limits, and commercial use allowed. There is no SLA. The
attribution "OpenFreeMap © OpenMapTiles Data from OpenStreetMap" is shown by MapLibre's attribution
control from the style. To self-host later, point `EXPO_PUBLIC_MAP_STYLE_URL` at another style.
